# ROCOS API 获取与维护

## 权威来源与范围

- 唯一维护源：[Apifox 项目 8387612](https://app.apifox.com/project/8387612)，模块 `7912103`（`ROCOS API`）。执行前确认连接指向该项目、模块和任务目标分支。
- 每次查询协议都通过 MCP 刷新并读取；每次更新都通过 MCP 回读验证。仓库 `docs/` 是辅助说明，不以历史文档、GitHub 旧 YAML 或缓存覆盖在线定义。
- 不重新引入受版本控制或持续维护的本地 OpenAPI 副本。必要的差异分析、备份和导入文件放在临时目录，不把凭据写入仓库或报告。
- 迁移时的 API 版本为 `3.0.0`，这是历史基线，不是需要强制恢复的版本。当前版本以在线读取结果为准；API 版本与应用 `package.json` 版本独立。

## 工具发现

在当前工具列表中发现 Apifox 能力，读取实际工具参数，不假定动态后缀或未来能力保持不变。创建本技能时，连接提供以下三个工具：

| 工具名片段 | 用途 |
| --- | --- |
| `refresh_project_oas` | 从服务器刷新最新协议 |
| `read_project_oas` | 读取协议索引及项目元信息 |
| `read_project_oas_ref_resources` | 按索引给出的 `$ref` 批量读取接口和模型资源，参数为 `path` 数组 |

这三个工具仅支持读取。不要把刷新工具当作上传工具，也不要声称已通过它们完成写入。

## 获取与核对

1. 先刷新，再读取索引，确认 API 版本及任务相关路径。刷新失败时明确说明无法确认最新状态；不要将旧缓存作为当前事实。
2. 从返回内容提取实际 `$ref`，批量读取相关 operation 和 schema，递归解析任务所需的引用。不要猜测资源路径；索引摘要不足以判断请求体、响应或鉴权。
3. 按 `HTTP 方法 + 路径` 识别接口。根据任务核对参数位置、必填性、请求体、响应码、媒体类型、模型约束及有效鉴权（包含全局继承和操作级覆盖）。区分“未读取”与“在线不存在”。
4. 控制权相关工作还要读取获取、释放、心跳及有关写操作的定义，核对凭据、TTL、续期触发条件、只读请求行为和失败处理。不要从旧说明直接推断当前规则。
5. 报告来源项目、分支、API 版本、读取范围及具体结论。若比较本地实现，指出差异及影响；用户仅要求比较时，不自行修改线上协议。

## 更新与同步

1. 按上述流程取得最新状态和受影响引用，形成具体的新增、修改、删除清单及预期结果。以用户指定的业务变更为依据；历史迁移中“以本地为准”不构成今后用旧 YAML 覆盖在线定义的规则。
2. 检查当前会话授权和工具能力。用户已授权相应写入、范围和目标时直接继续，不重复确认。优先使用可写 MCP；只有只读 MCP 时，可使用已获明确授权的官方 API、CLI 或界面方式，并仍以 MCP 回读验证。缺少替代方式授权时，先完成可审阅差异，再说明只读限制并请求所需授权。
3. 保持变更范围最小。优先局部修改；必须全量导入时，以最新远端为基础保留无关接口、模型和元数据，检查导入匹配及删除选项。删除废弃接口不自动授权删除关联或未匹配的模型；不得仅凭 `deprecated` 标记批量删除资源。
4. 更新 API 版本仅在本次要求覆盖时执行。分支合并、开启主分支 AI 编辑权限或其他权限变更须在授权范围内；已有授权覆盖时无需重问，工具拒绝时不要擅自切换到其他项目或扩大权限。
5. 写入前若远端已变更，重新读取并更新差异，保留他人修改。写入失败或部分成功时先读取实际状态，再决定补齐或修正，避免盲目重复全量导入。持续出现同一拒绝或验证差异且无法安全修复时，停止后续写入，报告已完成和未完成部分。
6. 写入完成后执行以下回读核验。只有核验通过才报告同步完成；导入成功响应、CLI 输出或本地文件生成都不是最终证据。

## 回读核验

通过 MCP 再次刷新、读取索引及受影响接口/模型，比较实际保存结果与预期；批量迁移时覆盖完整接口和模型集合，并检查无关资源未被误删。

重点检查：

- API 模块元数据中的版本和描述是否保存；导出预设如在本次范围内也需核对，避免预设仍输出旧版本。
- 新增、修改及删除的 `方法 + 路径` 集合是否正确；必填字段、枚举、响应码、媒体类型和引用是否完整。
- 鉴权是否保持预期的 AND/OR 语义。迁移后的受保护接口要求 `ControlToken` 与 `ClientId` 同时存在，应在同一个 security requirement 对象中：

  ```yaml
  security:
    - ControlToken: []
      ClientId: []
  ```

  两个独立数组元素表示 OR，语义不同。还要核对 security scheme 的真实 header 名称、位置及操作级覆盖，不仅检查方案名。

- 控制权获取、释放、心跳、凭据校验与续期规则是否符合本次预期。
- URDF 等原始 XML 响应是否仍为约定媒体类型下的字符串，未被导入器转换成对象或 JSON 响应封装。
- OpenAPI 3.0/3.1 的可空表示等格式差异可在比较时做语义归一化；不要忽略类型、必填性、鉴权或内容类型的真实变化。

接口和模型数量仅作辅助检查，不作为以后必须保持的固定目标。发现差异时在已授权范围内修正并重新回读；若尚有未验证项，明确报告，不能宣称全部完成。

## 完成与仓库衔接

简要报告项目/分支、API 版本、变更范围、MCP 回读结果及剩余问题。必要时更新仓库内受影响的接入说明或实现，但不复制完整在线协议。

仅创建或更新技能、文档不自动授权 Git 提交，也不触发应用版本递增。用户要求提交时，遵循仓库的 [project-versioning](../project-versioning/SKILL.md) 技能。
